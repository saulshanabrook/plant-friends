# Offline plant identification with PFAF

Replace the existing Swift/Xcode app with a responsive, installable PWA that identifies one camera-captured or uploaded plant photo locally and opens matching PFAF names, hazards, edibility, and uses offline. Start with the full BioCLIP 2 encoder and the actual catalog exported read-only from `../pfaf-data`; prove and measure real desktop-browser inference before interface polish. Use React and TypeScript for the app, and `uv` with `mypy` for Python preparation tools; physical phone testing and multi-photo identification are deferred.

The shared understanding is [facts.md](facts.md), with verification selections and retained review comments in [facts.meta.json](facts.meta.json). Follow the approved [execution plan](plan.md); its review decision is recorded in [plan-review.json](plan-review.json). The supplied [research handoff](research-handoff.md) is supporting material: the reviewed facts and plan take precedence, including the single-photo scope.

The goal is done when all accepted facts and their selected automated or manual checks are satisfied, the replacement PWA can be run locally from documented commands, and a real installed BioCLIP 2 pack identifies a previously unused local photo after an offline browser reload while PFAF search and details also work offline. Deliver pinned environments, reproducible asset preparation, numerical comparison and labeled-photo reports, desktop benchmark results, and a clear record of untested phone environments. Keep large generated model files out of git and preserve the sibling data repository.

A mock interface, Python-only inference, or unavailable-hardware state does not satisfy the identification requirement. If the full model/export/browser path proves impractical, document the precise evidence, propose an alternative before changing models, and leave the unsatisfied requirement explicit. Public publication, additional models, and the other deferred features in the fact sheet are outside this goal.
